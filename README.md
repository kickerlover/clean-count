# Чистый счёт

Мобильное приложение для iOS и Android: считает дни без алкоголя и курения, записывает срывы и показывает их в календаре. Главная идея: срыв обнуляет текущую серию, но накопленный прогресс сохраняется.

Реализовано по ТЗ «Чистый счёт» (MVP, разделы 2–9) и утверждённым макетам «Энергия».

> Если продолжаете работу с ИИ-агентом (Claude Code, Codex, Cursor), брифинг для него лежит в `AGENTS.md`: текущее состояние, первые задачи, риски, правила. Claude Code подхватывает его автоматически через `CLAUDE.md`.

## Стек

- **Expo SDK 57**, React Native 0.86, TypeScript (strict), Hermes
- `expo-router` — навигация
- `expo-sqlite` — локальное хранилище (WAL, миграции через `PRAGMA user_version`)
- `zustand` — состояние поверх БД
- `react-native-reanimated` + `react-native-gesture-handler` — анимации и жесты на UI-потоке
- `react-native-pager-view` — свайп между экранами привычек
- `@react-native-community/datetimepicker` — системный выбор даты и времени
- `react-native-svg` — иконки и диагональная заливка ячеек календаря
- Шрифты Unbounded и Golos Text вшиты в приложение (`@expo-google-fonts/*`)
- Локальный нативный модуль `modules/backup-exclusion` (Swift + Kotlin)

Сетевых запросов, аналитики и рекламы нет.

## Запуск

Нужны Node.js 20+, Xcode 16+ (для iOS) и Android Studio с JDK 17 (для Android).

```bash
npm install

# iOS-симулятор или подключённый iPhone (development build)
npx expo run:ios

# Android-эмулятор или телефон
npx expo run:android
```

Папки `ios/` и `android/` генерируются автоматически (Continuous Native Generation), руками их не правим. Нативные настройки задаются в `app.json`.

> **Xcode 27.** iOS 27 SDK требует жизненный цикл UIScene, иначе приложение падает на старте. В SDK 57 это включается плагином `expo-build-properties` с `ios.enableSceneSupport: true` (уже прописано в `app.json`). После обновления на SDK 58 настройка станет лишней, её можно будет убрать. Подробнее: https://github.com/expo/fyi/blob/main/ios-scene-lifecycle.md

Можно запустить и в **Expo Go** (`npx expo start`), но там нет локального модуля, поэтому переключатель «Не включать в облачный бэкап» будет неактивен. Всё остальное работает.

5. **Проверка**: `npm test`, затем `npx expo run:ios` — соберёт приложение и откроет его на симуляторе. Быстрая проверка без сборки: `npx expo start` и приложение Expo Go на телефоне.
6. **Загрузка новой версии**: поднять `ios.buildNumber` в `app.json` (и `version`, если меняется версия), затем `TEAM_ID=U8Z9KKJ636 scripts/archive-ios.sh --upload`. При первом запуске на новом Mac Xcode сам выпустит сертификат разработки для этой машины.

## Как устроен подсчёт

Производные показатели не хранятся, а каждый раз вычисляются из записей (`src/domain/stats.ts`).

- **Дата отказа** хранится как ISO-строка со смещением пояса (`2026-03-03T00:00:00+03:00`). Из неё берутся и момент времени, и исходная календарная дата.
- **День срыва** (`relapse.date`) фиксируется в локальном поясе на момент записи, поэтому смена пояса не сдвигает уже записанные дни.
- **Общий счёт** — календарные дни от даты отказа до сегодня (3 марта → 28 сентября = 209). Это основной счётчик на главном экране, срыв его не обнуляет. Под числом тот же срок в годах, месяцах и днях по календарю («6 месяцев 25 дней»); если в целевом месяце нет нужного числа, опорный день сдвигается на конец месяца. Меньше месяца строка не показывается.
- **Чистых дней всего** = общий счёт − уникальные дни со срывом.
- **Чистых дней с последнего срыва** — завершённые дни после дня последнего срыва (16 августа → 28 сентября = 42). Срыв сегодня или вчера даёт 0, без срывов значение равно общему счёту. Момент и порядок записи срывов роли не играют. Часы и минуты не считаются.
- **Срывы** — число записей с разбивкой по видам.
- **Следующая цель** — ближайшая веха больше чистых дней с последнего срыва, прогресс = дни / цель (42 из 45). Лестница вех: 5, 10, 14, 21, 30, 45, 60, 90, 120, 180, 270, 365, 545, 730 дней, дальше каждый год. После срыва цель начинается заново с 5 дней. Полоса цели показывается в плитке чистых дней.
- Срывы раньше даты отказа не учитываются, но остаются в базе: если вернуть дату отказа назад, они снова засчитаются.

### Часовые пояса и Hermes

Популярные библиотеки (`date-fns-tz`, `@date-fns/tz`) определяют смещение пояса через `Intl.DateTimeFormat` с `timeZoneName: 'longOffset'`, а Hermes этого не поддерживает. В итоге для имён вроде `Europe/Moscow` получается `NaN`. Поэтому в `src/domain/tz.ts` своя небольшая реализация:

- основной путь — `formatToParts`;
- запасной — разбор `format()`;
- если `Intl` с поясами недоступен совсем — локальное время устройства.

Все три пути покрыты тестами. Текущий пояс перечитывается через `expo-localization` каждую минуту и при возврате в приложение, поэтому смена пояса подхватывается без перезапуска.

## Решения по неоднозначным местам ТЗ

1. **Сегодняшний день в «чистых днях».** Сегодняшний день ещё не завершён, поэтому он не входит ни в общий счёт, ни в «грязные» дни. Благодаря этому срыв сегодня обнуляет серию сразу, а «чистых дней» становится меньше только завтра, и значение никогда не уходит в минус. Пример ТЗ (209 − 3 = 206) выполняется.
2. **Поздравления с вехами.** Вехи считаются по чистым дням с последнего срыва и привязаны к серии: в новой серии после срыва те же вехи поздравляются снова (`celebratedSince` и `celebratedUpTo` у привычки — с какого дня серия и до какой вехи в ней уже поздравляли). Если не показанных вех несколько (дата отказа в прошлом, долго не открывали приложение), показывается одно поздравление — с самой большой. Достижения (`milestonesEarned`) при этом копятся за всё время и срывом не обнуляются. Записи вех из прежних схем (значения вне лестницы) при загрузке переводятся на лестницу: заработанное значение засчитывает все вехи до него, поздравлений задним числом нет.
3. **Отмена записи срыва.** Запись сохраняется в базу сразу (требование надёжности), а «Отменить» удаляет её.
4. **Кнопка настроек** (в макетах её нет) — круглая кнопка рядом с календарём. Если привычка одна, вместо переключателя в шапке показывается название приложения.
5. **Кнопка «Был срыв»** закреплена внизу экрана, а контент над ней прокручивается. Так экран работает на узких экранах (360 pt) и при крупном системном шрифте.
6. **Добавление срыва из календаря** при фильтре «Все» и двух привычках сначала спрашивает, какую привычку записать.
7. **Итог месяца** при выбранном фильтре показывает только плитку этой привычки.
8. **Исключение из бэкапа.**
   - iOS: на папку с базой ставится флаг `isExcludedFromBackup`.
   - Android: исключать отдельные файлы из Auto Backup во время работы нельзя, поэтому база переносится в `noBackupFilesDir`, которую система никогда не копирует.
   
   По умолчанию бэкап разрешён, как в ТЗ.
9. **Минимальная iOS — 16.4**, а не 16.0: это минимум Expo SDK 57.
10. **Нижнее окно записи срыва** написано на Reanimated и Gesture Handler, без сторонней библиотеки. Закрывается свайпом вниз за верхнюю часть, тапом по фону, кнопкой «Отмена» и системной «Назад».
11. **Главный экран отличается от раздела 4 ТЗ** по решению владельца от 8 октября 2026: большая цифра — общий счёт с даты отказа и тот же срок в годах, месяцах и днях; под ней одна плитка той же формы с «чистых дней всего», «чистых дней с последнего срыва» и полосой цели; карточка срывов прижата к низу; часы и минуты не показываются и не считаются; вехи считаются по чистым дням с последнего срыва по лестнице 5, 10, 14, 21, 30, 45, 60, 90, 120, 180, 270, 365, 545, 730 и далее каждый год (вместо 1, 3, 7, 14, 30, … из ТЗ). В этой части ТЗ больше не источник истины.
12. **Экран достижений** (в ТЗ его нет): сводка по привычке, главные рубежи (месяц, три месяца, полгода, год, далее каждый год) и сетка вех: только текущая серия (закрашены) и ближайшая цель (пунктир); вехи прошлых серий свёрнуты в одну строку «Ещё N вех получено в прошлых сериях», а в главных рубежах помечены как «получено раньше». После срыва достижения не пропадают, а в новой серии те же вехи можно пройти снова. Вход: кнопка с кубком в шапке главного экрана и нажатие на полосу цели.
13. **Язык интерфейса.** Два языка: русский и английский. По умолчанию берётся язык устройства (русский, если система на русском, иначе английский), в настройках есть переключатель, выбор хранится в таблице `settings` и переживает сброс данных. Словари `src/i18n/ru.ts` и `src/i18n/en.ts` имеют одинаковую структуру (проверяется тестом), `t` — прокси на активный словарь, экраны подписаны на язык через `useLanguage()`. Название приложения на домашнем экране локализовано через `expo.locales` в `app.json`.
14. **Свои привычки (версия 1.1).** Помимо встроенных алкоголя и курения пользователь заводит до шести привычек всего (две встроенные плюс до четырёх своих) с названием (до 24 символов), эмодзи, цветом из палитры, единицей учёта при срыве (разы, штуки, порции, минуты, деньги) и необязательными видами срыва (до восьми, через запятую). Таблицы `habits` и `relapses` пересозданы миграцией 3: `id` привычки — строка (у встроенных прежние `alcohol`/`smoking`, у своих UUID), `preset` отличает встроенные, `kind` срыва — произвольная строка или `NULL`, `count` до 999 999 (деньги вводятся суммой). Встроенные привычки нельзя удалить, только выключить; своя удаляется вместе со срывами (каскад). Виды срыва у встроенных по-прежнему из словаря, у своих — как ввёл пользователь, поэтому не переводятся. Подписи «без алкоголя»/«без курения» у своих заменяются на «без срывов · Название». До трёх включённых привычек переключатель остаётся сегментным, дальше — строка чипов с эмодзи. В календаре день с несколькими срывами делится по диагонали на цвета первых двух привычек.
15. **Один масштаб для всех iPhone (версия 1.1).** Макеты нарисованы под iPhone 14 Pro Max (430 pt по ширине), и все размеры в коде заданы для него. На других моделях интерфейс не перевёрстывается, а пропорционально масштабируется: `src/theme/scale.ts` считает `SCALE = ширина / 430` (в пределах 0,8–1,1), `createStyles()` умножает на него размеры, отступы, радиусы и шрифты во всех стилях, а числа вне стилей оборачиваются в `s()`. Толщина линий и системное увеличение шрифта (`maxFontSizeMultiplier`) не масштабируются. На iPhone 17e (390 pt) масштаб 0,91, на iPhone SE (375 pt) 0,87.

## Что проверено, а что нет

Проверено автоматически:

- **107 тестов:**
  - правила подсчёта на данных из ТЗ;
  - срыв задним числом и два срыва в один день;
  - удаление срыва и смена даты отказа;
  - переход через полночь, смена часового пояса, перевод старых вех на новую схему;
  - вехи и склонения;
  - календарь;
  - свои привычки: проверка ввода, виды, лимит, календарь и подписи;
  - smoke-тесты экранов: запись срыва с отменой, календарь с удалением, онбординг, поздравление, добавление, правка и удаление своей привычки.
- `tsc` и ESLint без ошибок, `expo-doctor` 21/21.
- JS-бандлы собираются для iOS и Android, `expo prebuild` генерирует нативные проекты, автолинковка находит локальный модуль.

Не проверено, потому что на машине разработки не было Xcode и Android SDK:

- компиляция нативного кода;
- запуск на устройстве;
- соответствие макетам «на глаз».

## Чек-лист ручной приёмки (раздел 10 ТЗ)

- [ ] Настройка проходится за 3 экрана; можно выбрать одну или обе привычки и прошедшую дату отказа.
- [ ] Показатели совпадают с правилами (удобно проверить на прошедшей дате отказа и срывах задним числом).
- [ ] Свайп и переключатель меняют экраны синхронно, индикатор переключателя едет вместе с пальцем.
- [ ] Срыв записывается с типом, датой и (для курения) количеством; «Отменить» в течение 5 секунд возвращает прежние значения.
- [ ] Календарь: цвета срывов, диагональ при двух срывах в один день, фильтр, нажатие на день открывает подробности, долгое нажатие на срыв удаляет его.
- [ ] Удаление срыва из календаря пересчитывает показатели на главном экране.
- [ ] Данные сохраняются после перезапуска и работают в авиарежиме.
- [ ] Экраны соответствуют макетам «Энергия» на 360 и 430 pt по ширине.
- [ ] VoiceOver / TalkBack читают подписи кнопок-иконок и ячеек календаря; крупный системный шрифт не ломает вёрстку.
- [ ] Настройки: выключение и включение привычки, смена даты отказа (с предупреждением), переключатель бэкапа, сброс данных (двойное подтверждение).
